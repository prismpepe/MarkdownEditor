# Markdown エディタ 簡易仕様書

Windows 11 向けの Markdown 編集アプリ。左の編集欄に書くと、右のプレビューにリアルタイムで反映される（2画面方式）。

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| 名称 | Markdown エディタ（`MarkdownEditor.exe`） |
| 対象 OS | Windows 11（64bit） |
| 形態 | 単体の .exe（インストール不要、約12MB） |
| 実行に必要なもの | Microsoft Edge WebView2 ランタイム（Windows 11 に標準で入っている） |
| 用途 | Markdown 文書の作成・編集。フォルダー内の文書を一覧から選んで開く使い方にも対応 |
| 関連アプリ | 閲覧専用の「Markdown ビューア」とは別のアプリ。設定・バックアップの置き場所も別 |

## 2. 起動の仕方

| 起動方法 | 動作 |
| --- | --- |
| `MarkdownEditor.exe ファイル.md` | そのファイルを開く。同じフォルダーの Markdown 一覧も左に出す |
| `MarkdownEditor.exe フォルダー` | そのフォルダーの一覧を表示（文書は空の「無題」） |
| `MarkdownEditor.exe`（引数なし） | 前回のフォルダーがあればその一覧を表示する（前回開いていたファイルは開かない）。なければ案内を表示し、空の「無題」で始まる（ダイアログは自動では出さない） |
| `MarkdownEditor.exe --register` | エクスプローラーの「プログラムから開く」と、フォルダーの右クリックのメニューに登録（現在のユーザーのみ） |
| `MarkdownEditor.exe --unregister` | 上記の登録を解除 |

- 対象の拡張子は `.md` `.markdown` `.mdown` `.mkd`。
- フォルダーの右クリック：`HKCU\Software\Classes\Directory\shell\<キー名>`（`%1`）と `Directory\Background\shell\<キー名>`（`%V`、フォルダーの中の何もない場所）に登録する（`shellreg.py`）。キー名はアプリごとに別（`MarkdownEditor`）で、片方がもう片方を上書きしない。解除は、このアプリが書いたキーだけを消す。Windows 11 では、短いメニューには出ず、「その他のオプションを表示」の先の従来のメニューに出る。ドライブそのもの（`Drive\shell`）は対象外。ルート（`F:\`）を `"%V"` で渡されると、引数が `F:"` になるので、起動時に `F:\` へ直す（`shellreg.clean_path_arg`）。
- エクスプローラーからのダブルクリック起動は、登録のうえ、Windows 側で「常に使う」を選ぶ必要がある（Windows 11 の仕様で、既定のアプリはプログラムから切り替えられない）。

## 3. 画面構成

| 領域 | 内容 |
| --- | --- |
| ツールバー（最上段） | 新規／フォルダーを開く／ファイルを開く／保存／名前を付けて保存／印刷・PDF／更新／フォントの設定／表示の切替（3画面・2画面・編集のみ・プレビューのみ）／プレビュー倍率 |
| 一覧（左） | 現在のフォルダー、ファイル名の絞り込み、件数、Markdown ファイルの一覧（サブフォルダーごとの見出し付き） |
| 編集（中央） | 編集ボタンの列、検索・置換バー（開いたとき）、編集欄（行番号つき） |
| プレビュー（右） | 編集中の文書の表示 |
| ステータスバー（最下段） | 行・列、文字数、改行の種類、文字コード、状況メッセージ |

- 編集とプレビューの境界はドラッグで動かせる。
- ライト／ダークは Windows の設定に追従する。
- 表示の切替（`prefs.view`）は1か所の4モード。3画面＝一覧・編集・プレビュー、2画面＝編集・プレビュー、編集のみ、プレビューのみ。**一覧が出るのは3画面のときだけ**。Ctrl+1〜4 で切り替え、Ctrl+\ は3画面と2画面を切り替える。
- ウィンドウを狭めたときは、ツールバーをグループ（区切り線で分けた塊）の境目で折り返す。グループの中も、収まらなければ折り返す。ボタンの文字は折り返さない。

## 4. 機能

### 4.1 編集

- 編集欄は CodeMirror 5（同梱）。行番号、Markdown の色分け、取り消し／やり直し、折り返し、現在行の強調。
- Enter でリストの記号が続く。Tab は2文字分の字下げ（選択中は選択行の字下げ）、Shift+Tab は字下げを戻す。
- 編集欄の文字の大きさは Ctrl+ホイール、または Ctrl+`+` / `-` / `0`（編集欄に焦点があるとき）で変える。

### 4.2 編集ボタン

| グループ | ボタン |
| --- | --- |
| 編集 | 元に戻す、やり直し、切り取り、コピー、貼り付け、検索・置換 |
| 見出し | 見出し1〜6、本文に戻す |
| 文字の装飾 | 太字、斜体、取り消し線、コード |
| リスト | 箇条書き、番号付き、チェックリスト、引用 |
| 挿入 | リンク、画像、表、コードブロック、区切り線 |
| 図 | Mermaid のひな形（フローチャート、シーケンス図、クラス図、ガントチャート、円グラフ、`xychart-beta`、`radar-beta`、`quadrantChart`、`mindmap`、`stateDiagram-v2`、`erDiagram`、`architecture-beta`、`gitGraph` の13種類）と、Vega-Lite のひな形（棒グラフ、折れ線グラフ、CSV ファイルから）。`format.js` の `DIAGRAMS` と `CHARTS` |

- 同じ操作をもう一度行うと元に戻る（トグル）。複数行を選んでいれば、まとめて変換する。
- 箇条書き・番号付き・チェックリストの間は、そのまま変換できる。番号は連番。
- 読み取り専用の文書では、書き換えるボタンは使えない（コピーと検索は使える）。

### 4.3 検索・置換

- 一致をすべてハイライトし、「n / 全部で m 件」を表示。「大文字小文字を区別」「正規表現」を選べる。
- 次へ／前へは Enter・Shift+Enter・F3・Shift+F3。末尾まで来たら先頭へ戻る。
- 置換は、まず一致を選び、もう一度押すと置換して次へ進む。「すべて置換」は1回の取り消しで元に戻る。
- 置換後の文字列では、正規表現のときだけ `$1` `$&` `$$` が使える。
- 長さ0の一致（`^` だけなど）は一致の対象にしない。
- 数える上限は10,000件。

### 4.4 コピー・貼り付け・右クリックメニュー

- Ctrl+C / X / V / A / Z / Y は編集欄の標準の動作。
- ボタンとメニューからのコピー・貼り付けは、Windows のクリップボード（文字列）を直接使う。貼り付けでは Windows の改行を取り込める。
- 右クリックで、編集欄にはメニュー（元に戻す、やり直し、切り取り、コピー、貼り付け、すべて選択、検索、置換）、プレビューにはメニュー（コピー、すべて選択）が出る。

### 4.5 プレビュー

| 項目 | 内容 |
| --- | --- |
| 更新 | 入力が止まってから約0.2秒後 |
| 記法 | CommonMark、表、取り消し線、タスクリスト、見出しへのリンク。日本語の文では、括弧などの記号に接した `**強調**` も強調にする（前後が日本語の文字なら空白とみなす。CommonMark の厳密な規則とは異なる。`cjk_emphasis.py`） |
| 埋め込み HTML | 許可したタグだけ表示。スクリプト等は除去（4.10 参照） |
| 図 | Mermaid（` ```mermaid ` のコードブロック）。描いた図は「記述＋置き場所の幅」で記憶し、変えた図だけ描き直す。誤りのある図はその図だけ理由つきで表示。Architecture Diagram の追加アイコンは、同梱の iconify `logos`（約2,200個）が使える（`logos:slack-icon` など）。図でそのアイコンが要るときだけ読み込む |
| グラフ | Vega-Lite（` ```vega-lite ` のコードブロック。JSON）。SVG で描き、描いたものは「文書の場所＋spec」で記憶して、変えたグラフだけ描き直す。常に白地（ダークモードでも）。ライブラリは、グラフがあるときだけ読み込む。データは `data.values`（直接記述）、`data.url` の `http(s)` の URL、編集中の文書のフォルダー配下の相対パス（`.csv` `.tsv` `.json`、20MB まで）から読める。ウィンドウに戻ったとき、記憶を捨てて描き直す（別のアプリで直したデータに追従するため） |
| 画像 | 相対パスの画像は文書に埋め込んで表示（20MB まで）。保存先のない「無題」では相対パスの画像は解決できない |
| リンク | `http(s)` / `mailto` は既定のブラウザーで開く。他の Markdown への相対リンクはこのアプリで開く。それ以外のローカルファイル（PDF・Word など。許可した拡張子のみ）へのリンクは、関連づけられたアプリで開く（`Api.open_local`） |
| 位置合わせ | 編集側のスクロールにプレビューが追従する。打鍵中は、書いている場所をプレビューに出す |
| 倍率 | プレビューの倍率を10〜500%で変えられる。全体表示（横スクロールが要らない最大の倍率）あり |

### 4.6 ファイル

| 項目 | 内容 |
| --- | --- |
| 文字コード | UTF-8、UTF-8（BOM付き）、Shift-JIS（CP932）、UTF-16 LE／BE（BOM付き）を判別して開き、同じ形式で保存する。ステータスバーで変更できる |
| 判別できないとき | 文字を失わないよう、読み取り専用で開く |
| 改行 | CRLF／LF／CR を判別して保つ。混在していたら知らせ、保存すると多いほうにそろう。ステータスバーで変更できる |
| 新規文書の既定 | UTF-8（BOMなし）、CRLF |
| 保存 | 一時ファイルに書いてから置き換える（途中で失敗しても元のファイルを壊さない） |
| 表せない文字 | 選んだ文字コードで表せない文字があれば保存せず知らせ、UTF-8 への変更を提案する |
| バックアップ | 既存ファイルを上書きする前に、`%APPDATA%\MarkdownEditor\backup\` へ退避する。**置き場全体で直近5回分だけ**を残し、古いものは保存のたびに削除する（日時の名前の順。空になったフォルダーも消す。`.bak` 以外のファイルには触れない） |
| 他のアプリによる変更 | ウィンドウを前面に戻したときに検知。未編集なら自動で読み込み直す。編集中なら「読み込み直す／続ける」を聞く。保存の瞬間の競合は、上書きするかを聞く |
| 変更の検知の方式 | ファイルの更新時刻（ナノ秒）と大きさを「スタンプ」として覚え、保存時・前面に戻ったときに比べる。スタンプは画面との受け渡しを文字列（`更新時刻:大きさ`）にする（JavaScript の数値は 2^53 を超える整数を丸めるため、数値で渡すと、何も変わっていなくても変更ありと誤判定する）。読めないスタンプは「変更あり」として扱う |
| 保存ボタン | 未保存の変更があるときだけ強調色（`primary`）にする。マウスでは `mousedown` で保存を始め（編集欄からの焦点移動や日本語入力の確定で `click` が空振りしないように）、キーボード操作は `click`（`detail` が 0）で受ける。処理中は重ねて動かさない（`saveBusy`）。保存を始めるとステータスバーに「保存中…」を出す |
| 未保存の保護 | 閉じるとき、別のファイルを開くとき、新規を作るときに、保存するかを聞く |
| フォルダーの切替 | 「フォルダーを開く」で別のフォルダーを選ぶと、開いていた文書を閉じて空の「無題」にする。未保存の変更（書きかけの「無題」を含む）があれば、先に保存を促す。キャンセルしたらフォルダーも文書も変えない。同じフォルダー（大文字小文字・末尾の区切りの違いは同じとみなす）なら、文書は保つ |
| 文書の数 | 同時に開けるのは1つ（タブはない） |

### 4.7 ファイル一覧

- 選んだフォルダーのサブフォルダーを含めて Markdown を一覧にする（最大5,000件、最大10秒）。
- 読み込みの上限：件数（`MAX_FILES` = 5,000）か時間（`SCAN_SECONDS` = 10秒）の、どちらかに達したら、そこまでの一覧を返し、`truncated` で知らせる（`scan_markdown`）。画面は、件数の行に赤字で「（途中までです）」と出し、途中までの一覧は、ウィンドウを前面に戻したときに自動では読み直さない。
- 除くフォルダー：`.` で始まるもの、`.git`、`node_modules`、`__pycache__`、`.venv`、`venv`。
- ウィンドウを前面に戻したときに一覧を自動で取り直す。

### 4.9 印刷・PDF 出力

| 項目 | 内容 |
| --- | --- |
| 起動 | ツールバーの「印刷／PDF」、または Ctrl+P。空の文書では開かない |
| 出力の対象 | プレビューの内容（保存していない変更も含む）。画面の部品は含めず、本文だけを出力する（`@media print` で本文以外を隠す） |
| 出力先 | プリンターへの印刷、または PDF ファイルの保存 |
| ページ範囲 | すべて／指定（`1-3,5`、`5-`、全角も可）。誤りや全ページ数の超過は、理由を表示して実行させない。ページ番号は文書全体での番号のまま |
| 全ページ数 | 設定（用紙・向き・余白・倍率）を変えるたびに、PDF を作って数え直す |
| 用紙・向き・余白 | A4／A3／B5／B4／Letter、縦／横、標準（15mm）／狭い（8mm）／広い（25mm）／なし |
| 倍率 | 25〜200%。「幅の広い表は用紙に収まるよう縮小する」（既定オン）では、用紙の幅に入らないときに倍率を下げる（下限20%） |
| 背景・ヘッダー・フッター | 背景色の有無、ヘッダー（日付・ファイル名）とフッター（ファイルの場所・ページ番号）の有無 |
| 印刷のみの設定 | プリンター、部数（1〜99）、白黒 |
| 仕上がりの確認 | 設定どおりの PDF を一時ファイルに作り、既定の PDF アプリで開く |
| 配色 | ダークモードでも、紙面は明るい配色。Mermaid の図は、ダイアログが開いている間だけ明るい配色で描き直す |
| ページ分け | 表の行・図・画像・引用はページの途中で切らない。表の見出し行は各ページに繰り返す。長いコードは折り返す |
| 保存する設定 | 出力先、用紙、向き、余白、倍率、縮小、背景、ヘッダー・フッター、プリンター、部数、白黒。ページ範囲は保存しない |
| 実装 | Edge WebView2 の印刷機能（`PrintToPdfAsync`・`PrintAsync`）。`printing.py`（出力）、`print.js`（ダイアログ） |

### 4.10 安全に関する設計

編集中の文書は信頼できないため、プレビューではスクリプトが動かないようにしている。

- 埋め込み HTML は許可リスト方式（`sanitize.py`）。`<script>` `<style>` `<iframe>` `<form>` などは中身ごと除去し、`on…=` 属性、`javascript:` のリンクも除去する。`style` 属性は改ページの宣言（4.9a）だけ残してほかは除去する。
- Mermaid は `securityLevel: strict` で動かす。Mermaid 本体は同梱しており、図の描画にネット接続は要らない。
- **Vega-Lite のデータ読み込み（`data.url`）は経路を限定**する。
  - `http(s)` の URL：ネットから取得する（画像の `http(s)` と同じ扱い）。
  - 相対パス：Python 側（`Api.read_data`）で検査して読む。基準は、プレビューを作ったときの文書のフォルダー（`Api.render` に渡された保存先）。そのフォルダーとその下だけ。絶対パス、ドライブ指定、UNC、`file:`、`../` での外出、シンボリックリンクで外へ出るもの、`.csv` `.tsv` `.json` 以外、20MB 超は拒否する。保存先のない「無題」の文書では読めない。文字コードは、文書と同じ判定（UTF-8、UTF-16、Shift-JIS）。
  - それ以外のスキームは拒否する。
- **ローカルファイルへのリンク（`Api.open_local`）は、許可リスト方式**で開く。
  - 書き方：相対パス（編集中の文書のフォルダー基準。`../` 可）、`file:///C:/…`、`C:/…`。`sanitize.py` の `LINK_SCHEMES` に `file` を加え、開いてよいかは Python 側で判断する。保存先のない「無題」の文書では、相対パスは開けない。
  - 拒否：UNC・`file://サーバー/…`（ネットワーク共有への接続による情報の漏えいを避けるため）、存在しないファイル、`OPEN_EXTENSIONS`（`.pdf` `.doc(x)` `.xls(x)` `.ppt(x)` `.rtf` `.odt` `.ods` `.odp` `.txt` `.csv` `.tsv` と画像）以外。`.exe` `.bat` `.lnk` `.docm` `.xlsm` などは開かない。シンボリックリンクは、リンク先の実体でも同じ拡張子の検査をする。
  - 開く操作は、プレビューのリンクをクリックしたときだけ（`os.startfile`）。
- Vega-Lite 本体も exe に同梱しており、グラフの描画自体にネット接続は要らない（`http(s)` のデータを使う場合を除く）。

### 4.11 画面の設定と復元（`uiprefs.py`、`Api.get_prefs` / `set_prefs`）

- **フォント**：画面・編集欄・本文・見出し・コード・図の6部分で、フォント名と大きさ(px)を設定する（ツールバーの「フォント」）。見出しは名前と、H1〜H4 の大きさ(8〜120px。`--h1-size` など。空欄は本文に対する既定の比率)。名前は各部分につき1つだけ。入力欄は `datalist` の候補つきで、選んだ時点で値を一時的に空欄へ移して候補を全部出す。名前は CSS 変数（`--ui-font`、`--edit-font`、`--body-font`、`--head-font`、`--code-font`）に、大きさは `--ed-size` などに入れる。画面の大きさは、`toolbar`・`side`・`top`・`status`・`fmt` の CSS `zoom` で合わせる。図は Mermaid の `fontFamily` / `themeVariables.fontSize` とガントの寸法、Vega-Lite の `config` に渡す（変更時に図の記憶（`svgCache`、`vegaCache`）を捨てて、プレビューを描き直す）。システムのフォント名は、Win32 の `EnumFontFamiliesExW` で取り、入力欄の候補にする（取れなくても直接入力できる）。
- **編集欄の大きさ**：`fonts.editor.size` が唯一の保持先。Ctrl+ホイール／Ctrl+±／Ctrl+0 も同じ値を書き換える。旧版が保存した `prefs.editorSize` は、`fonts.editor.size` が無いときだけ、起動時に引き継ぐ。
- **復元する項目**：フォント、プレビュー倍率（全体表示かも含む）、ウィンドウの位置・大きさ・最大化、使用フォルダー（**開いていたファイルは復元しない**。誤って書き換えるのを防ぐため）、表示の切替（`prefs.view` = triple / split / edit / preview。一覧を出すかどうかも、これに含まれる）、編集とプレビューの境界（`prefs.split`）、印刷・PDF の設定。
- **旧い設定の引き継ぎ**：旧版は、一覧の表示を別のボタン（`side_hidden`）で切り替え、「2画面」は編集とプレビューだけを指していた。`prefs.layout_v` が 2 でなければ、起動時に、旧い `view` と `side_hidden` から新しいモードを決める（旧「2画面」で一覧あり → 3画面、一覧なし → 2画面。編集のみ・プレビューのみはそのまま）。
- **設定の保存は順番に処理する**：画面は、起動直後など設定を続けて保存し、呼び出しは別のスレッドで同時に動く。「読む→足す→書く」が重なると、先の書き込みが消えるので、`Api.set_prefs` はロックをかけて1つずつ処理する。
- **ファイル名を指定して起動した回**：使用フォルダー（`last_folder`）を保存しない（開いたファイルは、そもそも記録しない）。「フォルダーを開く」「ファイルを開く」「名前を付けて保存」で利用者が選び直したら、保存を再開する（`Api._persist_location`）。
- **ウィンドウ**：位置・大きさ・最大化は、閉じることが決まったとき（未保存の確認が済んだあと）に `WindowKeeper.save` で保存する。確認で「キャンセル」したときは保存しない。高 DPI で起動のたびに大きくならないよう、表示後に作成時の大きさと実測の比を測って補正する。保存した位置が画面の外にあるときは、位置だけ使わない。
- **安全**：設定ファイルは手で書き換えられうるので、読み書きとも `uiprefs.clean_*` で型と範囲を確かめ、範囲外はその項目だけ既定に戻す。フォント名からは、CSS を壊す文字（引用符・`;`・`{}`・`<>`・`\`・改行）を取り除く。

## 7. 制限事項

- 同時に開ける文書は1つ。タブ、分割編集、複数ウィンドウはない。
- 自動保存と、異常終了時の復元はない（保存は手動。上書き前の退避は残る）。
- 検索・置換は、開いている文書の編集欄のみが対象。プレビュー内の検索、複数ファイルをまたぐ検索はない。
- 表の列・行の追加や、番号付きリストの入れ子の振り直しなど、書式の高度な編集はない。
- 埋め込み HTML の `style` 属性による見た目の指定は効かない（改ページの指定だけは効く）。
- 数式（KaTeX など）、コードの色分け（プレビュー側）、HTML への書き出しはない（PDF 出力と印刷は 4.9 を参照）。
- ファイルのドラッグ＆ドロップで開くことはできない。
- 非常に大きな文書や、図の多い文書での性能は検証していない。
- 相対リンクで、このアプリの中で開けるのは Markdown ファイルのみ。PDF・Word などは、許可した拡張子に限り、関連づけられた別のアプリで開く。それ以外の種類は開かない。許可リストは `mdeditor.py` の `OPEN_EXTENSIONS` に固定している（設定では変えられない）。
- Mermaid の図は、プレビューの中の最終的な置き場所で描く（ガントチャートが親要素の幅で全体の幅を決めるため。画面外で描くとプレビュー幅より広く作られ、縮小されて文字が小さくなる）。プレビューの幅を変えたあとは、次にプレビューが更新されるときに、その幅で描き直す。
- Vega-Lite は式の評価に `new Function` を使う（`<script>` を動かさない方針とは性質が異なる）。厳密に揃えるなら `vega-interpreter` の追加が必要。
- Vega-Lite の `http(s)` のデータは、相手のサーバーが CORS を許可していないと読めない。
- Vega-Lite のグラフは常に白地で、ダークモードの配色には切り替わらない。印刷時の描き直しの対象外。
- バージョンは `mdeditor.py` の `APP_VERSION` で決め、ウィンドウのタイトルに出す。
- 署名のない exe のため、初回起動時に Windows の SmartScreen が警告を出すことがある。
- 登録（`--register`）は、書き込む内容を、テスト用の別のキーで確かめた（本物の登録を書き換えないため）。実際のエクスプローラーでの、フォルダーの右クリックから開く動作と、ファイルの関連づけ（既定のアプリにする）での起動は、利用者の実機で確認済み（Windows 11 では右クリックのメニューは「その他のオプションを表示」の中に出る）。
- 印刷では、両面印刷・給紙トレイ・用紙の種類など、プリンター固有の設定は指定できない。
- 印刷・PDF 出力は、自動検証（用紙サイズ、ページ数、ページ範囲、ダイアログの動作）を通しているが、実際の紙への印刷は、仮想プリンター（Microsoft Print to PDF）の受け付けまでしか検証していない。
- Architecture Diagram の追加アイコンは `logos` 集のみ。それ以外のアイコン集（`mdi:` など）は同梱しておらず、「?」の印で表示される。
